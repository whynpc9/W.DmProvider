# W.DmProvider R2 development source

This .NET 10 source establishes an independent assembly and namespace from the restored DM.DmProvider 8.3.1.47463 baseline. It provides parameter precision, local transactions, and isolated ownership of user and isolation-control statements. ReadCommitted is the default. Public ReadUncommitted and Serializable entry points are gated to server version 8.1.5.60. This is development source, not a supported production release.

Consult [the asynchronous I/O report](../../docs/implementation/reports/T13.md), [cancellation and deadline report](../../docs/implementation/reports/T14.md), [R2 scope](../../docs/compatibility/R2.md), [the R1 report](../../docs/implementation/reports/T12.md), [PR review corrections](../../docs/implementation/reports/R1-review.md), [main review follow-up](../../docs/implementation/reports/R1-review-followup.md), and their exact candidate manifests for validation status, source identity, package version, and package/loaded DLL hashes. [Task progress](../../docs/implementation/progress.json) records the delivery gates.

RequireTls accepts only verified, full-session TLS. Authorized non-TLS tests must explicitly select PlaintextAllowed. Native cipher interoperability and downstream EF acceptance have separate evidence records. The R2 code uses asynchronous socket/TLS I/O for Open, Prepare, Execute, Read, NextResult, local transaction controls and network cleanup, including bounded BLOB/CLOB materialization. Command cancellation targets its captured execution. After a send begins, cancellation or timeout aborts that physical session; callers must explicitly Close/Open before reuse. The driver does not reconnect or replay the operation. A sent commit without a confirmed response reports OutcomeUnknown, which takes precedence over cancellation or timeout. Read and NextResult receive a fresh frozen command budget per call; internal fetches and chunks share it. Cleanup has a separate finite budget. Exact acceptance status is recorded in the task reports; pooling and full streaming are outside R2. TLS certificate loading retains the existing initialization path.

Verification packs use a unique candidate version supplied by the validation command; the package version and loaded DLL hash must match the relevant report.

The primary ADO.NET types are in `W.Dm`. This is a source-level port, not a binary replacement for `DM.DmProvider`. See `THIRD-PARTY-NOTICES.md` for provenance and native dependency declarations.

`GetSchema("Tables")` and `GetSchema("Columns")` use the visible `ALL_OBJECTS` and `ALL_TAB_COLUMNS` dictionary views under the current account. Table fill factor, space limit, and row count are returned as `DBNull` because those values are not available from this path. Column size is also `DBNull`: dictionary `DATA_LENGTH` measures storage bytes and cannot safely replace the legacy logical size calculation. Other schema collections retain legacy queries and have not been validated for a least-privilege account in T05.

R1 uses non-nested block-comment parsing. Typed getters reject SQL NULL with DmException 6081; GetValue and object/DBNull getters still return DBNull. Callers should use IsDBNull before reading nullable values. LOB materialization is limited to 64 MiB of returned payload (BLOB bytes, CLOB UTF-16 bytes, or hex string UTF-16 bytes); oversized values fail without truncation. CLOB GetChars supports null destination length probes within this limit. This bounds value payload rather than total working memory and does not provide streaming semantics. On the verified profile, strict single user/EF savepoint statements remain supported; the WSP_ server-name prefix is reserved for driver controls and is rejected in user SQL. Confirmed executions update a shared ordered savepoint stack. A raw rollback or release invalidates later API points; unknown or ambiguously matched targets conservatively invalidate tracked points. Prepare and failed execution do not update the stack. Assigning a command connection to null detaches it after releasing its own statement; clear an active explicit command transaction first, and close active readers before changing the connection.

Async schema discovery on the connection is explicitly unsupported; cached Reader schema and values can complete immediately. Client timeouts use DmTimeoutException (ErrorKind Timeout, symbolic WDM_TIMEOUT, Number 0). DmOperationCanceledException preserves the caller token and carries immutable failure metadata; WDM_COMMIT_UNKNOWN identifies an unconfirmed sent commit. FailureInfo distinguishes NotSent, ServerReported and Unknown without inventing server error numbers. Savepoints remain gated to 8.1.5.60; the independently tested TLS 8.1.4.6 profile rejects those APIs before sending.

A canceled or invalidated Reader can report IsClosed=true before releasing its execution lease and frozen command plan. Always Close/Dispose it, or use using/await using, even when IsClosed is already true. Until that release, command settings remain frozen. Cleaning up an old Reader cannot close a replacement session.
