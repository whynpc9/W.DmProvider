# W.DmProvider development source

This .NET 10 source establishes an independent assembly and namespace from the restored DM.DmProvider 8.3.1.47463 baseline. It provides parameter precision, local transactions, and isolated ownership of user and isolation-control statements. ReadCommitted is the default. Public ReadUncommitted and Serializable entry points are gated to server version 8.1.5.60. This is development source, not a supported production release.

Consult [the asynchronous I/O report](../../docs/implementation/reports/T13.md), [cancellation and deadline report](../../docs/implementation/reports/T14.md), [R2 scope](../../docs/compatibility/R2.md), [the R1 report](../../docs/implementation/reports/T12.md), [PR review corrections](../../docs/implementation/reports/R1-review.md), [main review follow-up](../../docs/implementation/reports/R1-review-followup.md), and their exact candidate manifests for validation status, source identity, package version, and package/loaded DLL hashes. [Task progress](../../docs/implementation/progress.json) records the delivery gates.

RequireTls accepts only verified, full-session TLS. Authorized non-TLS tests must explicitly select PlaintextAllowed. Native cipher interoperability and downstream EF acceptance have separate evidence records. The R2 code uses asynchronous socket/TLS I/O for Open, Prepare, Execute, Read, NextResult, local transaction controls and network cleanup, including bounded BLOB/CLOB materialization. Command cancellation targets its captured execution. After a send begins, cancellation or timeout aborts that physical session; callers must explicitly Close/Open before reuse. The driver does not reconnect or replay the operation. A sent commit without a confirmed response reports OutcomeUnknown, which takes precedence over cancellation or timeout. Read and NextResult receive a fresh frozen command budget per call; internal fetches and chunks share it. Cleanup has a separate finite budget. Exact acceptance status is recorded in the task reports; pooling and full streaming are outside R2. TLS certificate loading retains the existing initialization path.

Verification packs use a unique candidate version supplied by the validation command; the package version and loaded DLL hash must match the relevant report.

The primary ADO.NET types are in `W.Dm`. This is a source-level port, not a binary replacement for `DM.DmProvider`. See `THIRD-PARTY-NOTICES.md` for provenance and native dependency declarations.

`GetSchema("Tables")` and `GetSchema("Columns")` use the visible `ALL_OBJECTS` and `ALL_TAB_COLUMNS` dictionary views under the current account. Table fill factor, space limit, and row count are returned as `DBNull` because those values are not available from this path. Column size is also `DBNull`: dictionary `DATA_LENGTH` measures storage bytes and cannot safely replace the legacy logical size calculation. Other schema collections retain legacy queries and have not been validated for a least-privilege account in T05.

R1 uses non-nested block-comment parsing. Typed getters reject SQL NULL with DmException 6081; GetValue and object/DBNull getters still return DBNull. Callers should use IsDBNull before reading nullable values. LOB materialization is limited to 64 MiB of returned payload (BLOB bytes, CLOB UTF-16 bytes, or hex string UTF-16 bytes); oversized values fail without truncation. The limit applies to full materializing APIs and bounds returned payload rather than total working memory. R3 BLOB ranges and CLOB UTF-16 length scans use independent bounded cursors; CLOB GetBytes remains a compatibility API that fully materializes encoded bytes under this limit. On the verified profile, strict single user/EF savepoint statements remain supported; the WSP_ server-name prefix is reserved for driver controls and is rejected in user SQL. Confirmed executions update a shared ordered savepoint stack. A raw rollback or release invalidates later API points; unknown or ambiguously matched targets conservatively invalidate tracked points. Prepare and failed execution do not update the stack. Assigning a command connection to null detaches it after releasing its own statement; clear an active explicit command transaction first, and close active readers before changing the connection.

Async schema discovery on the connection is explicitly unsupported; cached Reader schema and values can complete immediately. Client timeouts use DmTimeoutException (ErrorKind Timeout, symbolic WDM_TIMEOUT, Number 0). DmOperationCanceledException preserves the caller token and carries immutable failure metadata; WDM_COMMIT_UNKNOWN identifies an unconfirmed sent commit. FailureInfo distinguishes NotSent, ServerReported and Unknown without inventing server error numbers. Savepoints remain gated to 8.1.5.60; the independently tested TLS 8.1.4.6 profile rejects those APIs before sending.

A canceled or invalidated Reader can report IsClosed=true before releasing its execution lease and frozen command plan. Always Close/Dispose it, or use using/await using, even when IsClosed is already true. Until that release, command settings remain frozen. Cleaning up an old Reader cannot close a replacement session.

R3 work is in progress; [the R3 design](../../docs/implementation/R3-design.md) and task progress identify the accepted stages. T15 has independently verified conservative physical discard on the two tested profiles. The independently accepted T16 implementation adds `DmDataSource`, `Pooling` (default false), `MaxPoolSize` (default 100), `MaxPoolWaiters` (default 1024), and a total `PoolAcquireTimeout`. `ConnPooling` and `ConnPoolSize` remain aliases. This is capacity scheduling with a fresh authenticated physical session for every lease: session reset is unproven, all returned sessions are discarded, and no handshake performance improvement is claimed.

Each explicit data source owns a separate capacity domain and keeps its internal credentials independent of its redacted ConnectionString. Shortcut commands hold their connection until a returned reader is closed/disposed. Clear retires the same domain without interrupting a business lease; disposing a data source refuses new opens and ends waiters, while existing business leases may complete. Direct connections with Pooling=true share a bounded registry only when no explicit TLS certificate files are configured. Direct pooling with such files is explicitly unsupported; use a DmDataSource with its independent capacity domain. Certificate file bytes are not advertised as an immutable snapshot; recreate the data source after certificate rotation. Statement pooling remains unsupported. T17 streaming LOB code has passed complete offline and TLS-profile acceptance; shared-profile streaming and its exact cleanup remain pending. T18 diagnostics and its fixed TLS resource soak passed independent acceptance for the recorded T18 candidate. T25 caller-boundary review then corrected a shortcut disposal race and confirmed-transaction diagnostic results; its new candidate passed 875 offline tests and exact-package TLS pool regression. The final T19 package, complete downstream contract and shared-profile gates remain pending. Reader GetStream/GetTextReader are forward-only, lazy and tied to the current row, execution and transaction. Close a field flow before opening another; advancing or closing its parent invalidates it. GetBytes supports bounded BLOB ranges; GetChars uses UTF-16 offsets and independently scans a null destination for length. Character columns (types 0/1/2/54) and CLOB use the declared server charset; ROWID keeps its local rendered-character compatibility through GetChars and is rejected by GetTextReader. Other scalar-to-character conversions are outside this streaming surface. CLOB GetBytes retains its materializing encoded-byte compatibility behavior and the 64 MiB payload limit. SequentialAccess rejects backward access and a change between consumed CLOB byte and UTF-16 units. Streaming parameter values require explicit DmSqlType=Blob for Stream or Clob for TextReader and Input direction. Inputs remain caller-owned; no Length, Position, Seek, rewind, disposal or automatic replay is performed. Repeated execution reads from the current input position; bind a fresh input when replaying intentionally. One input object cannot serve multiple SQL marker occurrences. The verified profiles expose NCLOB declarations as the same TEXT/CLOB wire type and server codec; a distinct national codec is not claimed.

Standard diagnostics use ActivitySource and Meter name `W.DmProvider`. Driver records contain bounded enum/numeric metadata and explicit trace parent identifiers; they exclude SQL, parameter values, connection strings, exception text, baggage and trace state. Export runs through a bounded background dispatcher. Queue saturation may drop spans and duration samples; cumulative counters are stored independently and remain observable. Read cumulative measurements as totals per fixed tag bucket, rather than adding repeated observations. Use `DmDiagnostics.FormatException` for known safe failure metadata; it does not read arbitrary exception Message, Data, stack or inner text. Diagnostic delivery is best effort and does not change a confirmed transaction result.

To roll back adoption, pin the explicitly recorded earlier candidate and disable new direct pooling, dispose data sources and create fresh connections. A sent commit with OutcomeUnknown requires application reconciliation; never replay it merely because a diagnostic/export operation failed.
