# T03 product source and API compatibility

T03 creates a local development candidate under assembly and package identity `W.DmProvider`, targeting `net10.0`. The primary ADO.NET namespace is `W.Dm`. This candidate is not an R1 release and is not published.

## Provenance and transformation

The fixed official `DM.DmProvider 8.3.1.47463` assembly was the input to the accepted T02 R restoration. For this import, the accepted restoration tool's three input-file hashes matched `docs/implementation/evidence/T02-validation.json`, and a new `.local/t02/t03-seed` was generated. Its 241 candidate C# files were byte-identical to the default restored tree. `t03-source-map.json` records source and product SHA-256 for 241 C# files, two neutral resources, and four culture resources. R bin/obj, the temporary normalized reference DLL, R project file, original assembly metadata, and official satellite DLL binaries were not imported.

The import parses C# syntax to migrate namespace identifiers: `Dm.*` to `W.Dm.*`, `A` to `W.Dm.Internal.Legacy.A`, and `NetTaste` to `W.Dm.Internal.Legacy.NetTaste`. The two former global event args move to `W.Dm`. The recovered core source filenames for `DmCommand` and `DmDataReader` are readable in `PublicApi/`. Literal SQL, reflection strings, and resource keys retain their original bytes. `DmConst.res` explicitly looks for the unchanged `Dm.DmErrorDefinition` resource base name; the `Dm.ReservedWords.txt` lookup remains unchanged.

The neutral resource has 240 keys. Four culture `.resx` files were extracted from the fixed official satellites (en 238 keys; zh-CN, zh-HK, zh-TW 240 each), then rebuilt by the W project into `W.DmProvider.resources.dll` for each culture. The culture-specific resource names retain `Dm.DmErrorDefinition.<culture>.resources`; they do not carry the official satellite binary identity. No original core or satellite DLL or native library is included in the product project.

The project suppresses Git SourceLink and revision metadata until the new W source has a real source commit. `AssemblyVersion` remains `0.1.0.0`; `InformationalVersion` follows the explicitly passed candidate `Version`. The official DM author and 8.3 assembly attributes were excluded. The package notice preserves upstream source attribution.

## API classification

`t03-api-map.json` maps each of the 3,651 visible R entries to a distinct W entry. The built W DLL exports exactly 3,651 entries with no additions. The ten primary ADO.NET types and their members are `preserved` (731 entries); other callable legacy compatibility entries are `obsolete` (2,920 entries). `obsolete` is a **documentation-only compatibility policy** in T03; no `[Obsolete]` attribute was added. No entry was marked `internalized` or `unsupported`, because T03 did not change accessibility or disable a callable path. `verification_state=untested` on every entry keeps static surface presence separate from behavioral acceptance. The old assembly cannot be binary-swapped with W because assembly and type identity changed.

The inherited advanced paths remain callable and unverified. In particular, the source still contains the old SYSDBA defaults, `InitialCatalog` changing credentials, mutable configuration/filter state, pooling/reconnect/read-write routing, distributed enlistment, old TLS protocol selection, and native FLDR/cipher calls. The old SkyWalking assembly string hook was intentionally left unchanged. These are explicit T04 and later R1 release blockers, not supported capabilities or guarded features in T03. T04 owns immutable settings, safe defaults, capability guards, and configuration semantics; later tasks own transport/TLS and advanced behavior verification.

The C# source declares native imports of `dmcalc.dll`, `dmcyt`, `dmfldr`, and Windows `Kernel32.dll`. The declarations identify potential runtime dependencies, not redistributed assets or evidence of permission to redistribute them. See `THIRD-PARTY-NOTICES.md`.
