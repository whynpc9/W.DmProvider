# T06 传输与帧边界

状态：T06 已通过独立验收；实际范围见 [T06 报告](../implementation/reports/T06.md)。

- 连接建立使用一份单调时钟预算，覆盖 DNS、多地址 TCP 尝试、STARTUP、LOGIN 和初始化。一次成功 Open 不再关闭 socket 后重新 Connect。
- Command 的执行期限覆盖本次消息循环。Reader 后续公开调用各自获得预算，用户在调用之间的停顿不计入下一次 Read。零超时代表无限；有限预算过期不会转换成 socket 的无限等待。
- Socket 发送处理短写；接收先精确取得 64 字节头，再按核实的长度获取正文。EOF、零进展、负长度、溢出、超限、校验失败和不支持的压缩模式明确拒绝。
- 一个总帧最多 64 MiB，这是当前产品保护值。该值不是服务端协议最大值，也不代表完整结果集的总堆内存上限。解码的行/引用数组和 BDTA 值另受预算约束。
- heartbeat 按完整帧消费、校验，并共用原期限。当前 CMD=200 的头 XOR 与协商后的正文 CRC 使用不同条件，详见 [字段证据](../implementation/T06-frame-layout.md)。
- `b` 的解码读取受实际有效长度限制；尚未支持的复杂类型描述符解码明确拒绝，避免无界递归。
- 同步调用仍为同步。TLS/native、端到端异步和完整取消/未知结果分类分别由 T07、T13/T14 处理；默认 RequireTls 在本阶段仍不开放。

本轮保留 T05 的会话所有权和故障后断开策略。既有连接打开的异常包装仍可能保留官方错误编号；不能据此宣称完整的超时/取消分类已经完成。
