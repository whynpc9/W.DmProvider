R 是内部恢复对照基线，保留官方程序集身份，禁止打包发布。W 的产品身份、namespace 和包依赖隔离属于 T03。当前结果不代表完成全部驱动能力或下游 EF 验收。

## 改动与分工

主 agent 负责 [恢复设计](../T02-design.md)、代码审阅和验收；两个 Sol High 分别实现恢复器与 O/R 对照宿主；Sol Low 独立验证；Luna Max 生成 Unicode、LOB 与 byte 转换的确定性数据。

- [RestoreBaseline](../../../tools/RestoreBaseline/README.md) 从固定资产和只读源码生成 `.local/t02/restored/`，再从 C# 编译 `DM.DmProvider.dll`。元数据归一化 DLL 只是反编译输入，不是 R 产物。
- 固定 SDK 10.0.203、C# 13.0、Mono.Cecil 0.11.6、ilspycmd 10.1.1.8388。R 目标 net9.0；两个独立宿主运行于 net10.0，O 从固定官方包恢复，R 只引用恢复工程。
- 按元数据 token 机械改名 50 个字段、25 个方法，重新生成 25 个受影响类型；另补一处有原 IL 依据的显式 byte 转换。来源未改动，没有顺带修复上游缺陷。
- [来源映射](../../../upstream/DM.DmProvider/8.3.1.47463/source-map.json)记录 token、原签名、改名原因及源码路径。每个 rename 的 `original_type` 对应 `regenerated_types` 中的目标文件；调用方关联由 `referenced_renames` 记录。
- [O/R 宿主](../../../eng/T02.md)共用场景代码，但分进程、输出目录和包缓存运行。比较器检查实际 DLL 身份、退出码、功能断言、清理状态及结果完整性。

## 恢复期间发现并修复的问题

首次 R 虽能编译，却在 Open 阶段失败，外层为 6001，底层为 6080。恢复器改名了基类虚方法 `A.a::a`（`0x06000A4D`），未同步派生 `A.D` 的 override（`0x06000A5E`），使调用落到基类空实现，未接收到握手数据。

修复为按原虚方法槽传播改名，记录基类与派生 token，并在内存归一化、写盘回读及编译后反射三个环节检查关系。初次失败证据保存在 `.local/verification/t02/pre-slot-fix/`，没有计入通过。修复未改变协议或版本门槛。完整恢复差异见 [restoration-diff.md](../../../upstream/DM.DmProvider/8.3.1.47463/restoration-diff.md)。

恢复器对 4,782 个方法体做原始、归一化和写盘回读的规范化指纹核对，并捕获 411 条模块内 override 关系、验证其中受改名影响的一条。该审计由恢复器产生并经主 agent 审阅；独立验证者没有另写第二套 IL 审计实现。方法体相同本身不能证明元数据分派关系或新编译资产的行为相同。

## 限制与交接

两份独立生成目录的 250 个输入文件 hash 相同：242 个 C#、1 个项目文件、5 个 DLL 输入（4 份卫星及归一化参考 DLL）、1 个 resx、1 个文本资源；排除了 bin、obj 和含目标路径的 source-map。不同目录生成的 R DLL hash 不同，因此本轮证明的是恢复过程可重复，不保证跨目录字节级重现。

R clean build 的 86 条旧代码警告保留，未为消除警告修改上游行为。真实 SQL 和修复检查覆盖本轮声明范围，没有做全部协议路径、TLS、并发池化、性能或下游 EF 回归。源码映射保留改名成员的后续差分验证标记；未运行的高级入口不能据此宣称支持。
