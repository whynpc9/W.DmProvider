状态：integration_verified，T11 范围完成。root 设计与 code review，GPT-6.1 Sol High 编码，GPT-6.1 Sol Low 独立验证。完整 R1/EF suite 继续 T12。

## 已确认的原缺陷

固定官方 O 与恢复版 R，在 RU/Serializable 下将隔离控制 statement 借给用户 Command，statement owner SQL 为空。完整 NextResult 在 GetCommandText 失败。相同 DLL 只清除用户命令继承的 statement 引用，保留 SQL/参数/事务，故障消失，独立连接确认回滚后状态正确。RC 对照成功。

ADO 最小 causal 证据：`.local/verification/t11/20260930T030043Z-baseline.json`。固定 EF commit `113014cc74dd1f751ef97226a78d2ec855b32c8c` 的 O 消费者 24 项中，RC 8 项正常、RU/Serializable 各 8 项观察到同根因失败；全部事务结束及清理确认，分类为 OfficialCharacterization。证据：`.local/verification/t11/20260930T030443Z-ef-O.json`。

## 候选修复

- 隔离控制 statement 有独立明确 SQL 的 owner，受同一 root lease 管理；配置 child 结束后使用有限 cleanup child 关闭，再检查 Begin 原始期限并激活事务。不会借给用户命令。
- Command.Transaction 不再采纳 transaction.Stmt，已有 prepared statement 保持当前 Command 的所有权和捕获的物理会话检查。
- EF 的单条 `ROLLBACK TO "name"` 与 `ROLLBACK TO SAVEPOINT "name"` 均通过窄词法守卫。名称可带双引号转义和注释；缺名、尾随 token、额外语句及完整 ROLLBACK 拒绝。SQL 原文不改写。
- 实测 SET 返回的是事务级 type150 和隔离值 0/3，会话默认缓存仍为 RC。候选不再用连接默认值等于请求值作为确认，改以响应 type150、request5、SQL code0、确切隔离值和完整 invocation identity 的 receipt 验证。错误或不匹配响应 fail closed。
