## 实现

- STARTUP 完整解析后、LOGIN 编码之前执行策略。wire 0 仅允许显式 PlaintextAllowed；wire 1/4 严格验证后升级原 TCP socket；AUTH_ONLY=2、wire 3/5/6 和未知模式拒绝。密码/消息 native cipher 与 TLS 分开处理，仍未开放。
- 新增 typed CA、客户端 PFX/PEM、私钥路径/口令和吊销策略。默认系统信任与 Online；显式 CA 使用自定义信任链，校验 CA 约束和签名用途，服务器证书保留名称、有效期及 serverAuth 用途验证，无恒真回调。
- TLS 升级和业务传输保持同一 socket、同一连接预算。待认证及已激活的 channel 均可由 Close 中止；先关闭捕获的物理 socket，再释放 SSL 和证书 scope，避免重复释放或恢复旧会话。
- 原 dmcyt/dmfldr/dmcalc/Kernel32 直接导入路径明确拒绝；预备 NativeLibrary/SafeHandle loader 只接受规范绝对路径，必需导出检查失败会释放。WithExport 在 callback 期间持有 SafeHandle，防止并发 Dispose 提前卸载。loader 的存在不表示原生算法已实现。

## 实测修正与限制

- 初期探针错误读取连接配置副本的 Encrypt=0，后改为观察 STARTUP 解析后的物理会话值。mode 5 的首轮失败是错误预期 wire 5，最终依据实际返回 4 修正测试合同并保持 wire 5 拒绝。
- Docker 端口代理 ready 早于 DM ready，最初模式矩阵过早连接而失败。现在按官方 TEST 登录确认 ready，并支持 owned 容器异常退出后的 mode 1 恢复；每轮 finally 恢复并实际登录核验。历史失败均保留，不计通过。
- macOS 的 PFX EphemeralKeySet 实测不支持，现显式采用 .NET 临时磁盘 keychain 的 DefaultKeySet，不使用 PersistKeySet/MachineKeySet；Windows/Linux 保留 EphemeralKeySet。macOS 不能宣称私钥完全不落盘，异常退出的清理依赖运行时/OS。[微软平台说明](https://learn.microsoft.com/en-us/dotnet/standard/security/cross-platform-cryptography#read-a-pkcs12pfx)。
- 本机 CA 没有 CRL/OCSP，真实测试显式选择 NoCheck；产品默认仍为 Online。真实 Online 吊销联网路径没有在此环境验收。
- native 错误和释放由受控 backend 测试；未声明实际原生 cipher、FLDR、计算库互操作。未知 native/TLCP 不降级为明文。
- 镜像记录的许可到期日是 **2026-10-13**。之后复现需有效介质或许可，不绕过期限。
