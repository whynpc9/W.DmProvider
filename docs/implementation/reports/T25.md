## 发现与修复

v1 新输入 fixture 的请求44末帧响应 opcode 不符真实协议，修正仅合成响应，产品未改。v2 发现实际 cleanup 竞态：内部 command 已 Dispose，reader 随后解除绑定抛 ObjectDisposedException。Release 保持 expected connection 身份与原关闭/permit 次序，已 Dispose 时跳过 setter；检查后竞争只消解准确 ObjectName 且 shortcut 确已 Dispose 的异常。setter 在 lifecycle gate 外，其他异常不吞。

v3/v4 隔离出实际诊断错误：Commit 已获 ACK 并确定 Committed，旧 invocation 未调用 Complete，导致 success 被分类为 TransportError。Session 在既有 gate 复制最终 Commit/Rollback outcome；诊断 Unknown 优先、Confirmed success 其次，不改变原 ACK、Completed、取消或业务事务状态。Commit 强断言保留，并补独立 Rollback public ACK。所有失败轮次保留在 [T25 evidence](../evidence/T25/)，原断言未弱化。
