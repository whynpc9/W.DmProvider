# T10 本地事务与保存点

日期：2026-09-30。状态：**integration_verified，T10 同步事务范围完成**。主 agent 设计/审阅，GPT-6.1 Sol High 完成最终修复，GPT-6.1 Sol Low 独立执行验证。隔离语义及真实 EF SaveChanges 矩阵属于 T11，token 竞争属于 T14。

## 实现

- 每个事务持久记录自己的 outcome，并绑定原物理会话。发送尝试紧贴 transport 写入；只有匹配操作的完整成功响应才确认 Commit/Rollback。提交发送后结果不明抛非 transient 的 DmCommitOutcomeUnknownException，不重放。
- Active 用户命令必须显式绑定同一事务，计划预检和获得 lease 后均检查。旧句柄不能影响重新打开的连接。Valid/Clear/_disposeStatus 不能再伪造生命周期或跳过清理。
- Begin 的 Unspecified 解析为 ReadCommitted；Active 表示本地句柄与已确认配置就绪，不虚构 DM 不存在的独立 BEGIN ACK。其他隔离级别尚未开放。
- Dispose 尝试有界关闭活动 Reader，再按同一个绝对 CleanupTimeout 回滚；不能安全同步时关闭原会话且保留未确认状态。显式控制共享 CommandTimeout 根期限，0 可无限；清理始终有限，并保留注入的时钟。
- 保存点名称映射到短 ASCII 标识符，重复替换、回滚/释放后继失效、名称和总量限制已验证。已测 profile 使用真实 SAVEPOINT/ROLLBACK TO/RELEASE SQL，非逻辑假释放。
- 普通服务器错误继续保守关闭；仅已测 profile 的完整 `-2106` 错误响应，在四段错误体严格解析、精确 invocation 匹配后允许有限 statement-close，并保留 Active 供显式 Rollback。截断、坏长度和其他不确定错误不因此放宽。
- 不参与 ambient 的本地事务不再读取 Transaction.Current；非空 enlist/promotable 路径明确拒绝。

## DDL 与确认边界

真实 **8.1.5.60** 逐响应探针证明 INSERT 业务帧的事务状态为活动，结果终结帧会覆盖旧缓存。实现因此只采纳已验证业务响应，忽略 prepare/终结帧的伪终结效果。

CREATE/ALTER/DROP/TRUNCATE TABLE 的返回类型分别为 129/146/139/194，业务状态结束，且之前写入在新连接中可见。旧 O/冻结 W 即使随后收到 Rollback ACK，也无法撤销这些写入。W 对已证形态标记 CompletedExternally、使旧事务失效。Active 内只允许已测 profile 的**单条无参数 TABLE DDL**；混合/参数化 DDL、未证 DDL 或 profile 明确早拒。正常 DML 复合 SQL、WITH 和 EF 保存点路径不因此禁用。

ACK/Close 竞争的真实 barrier 测试曾发现：Close 清空 B 的连接字段后，已成功收到的 ACK 仍访问该字段，引发空引用并误报 Unknown。修复改用 invocation 持有的原会话；确认旧事务不接触新会话。失败轮次保留，未放宽断言。
