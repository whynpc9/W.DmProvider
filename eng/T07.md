# T07 TLS and native boundary acceptance

`eng/t07.sh offline` runs `W.DmProvider.SecurityTests` with a strict TRX gate, reruns T04 configuration tests under the new STARTUP negotiation policy, builds `SecurityProbe`, and runs `eng/t06.sh offline` (which includes T05 ownership regression). Every test must be executed and passed; skipped, failed, aborted, pending, warning, and other nonpass counters must all be zero. Offline success reports `integration_pending`.

The offline suite uses temporary `CertificateRequest` CA/server/client certificates and a loopback `SslStream` server. It checks DNS/IP SAN, trusted and unknown CA, expiry, wrong host, server EKU, explicit mTLS client certificate in PEM and password-protected PFX forms, default Online versus explicit NoCheck revocation selection, TLS deadline and Close resource release, negotiated mode policy, and fake native loader ownership. On macOS, PFX loading explicitly uses the runtime's temporary keychain (`DefaultKeySet`) because .NET does not support `EphemeralKeySet` there; the certificate scope disposes its reference on Close/failure. This permits temporary private-key storage by the runtime, so the PFX test is not a no-disk assertion. Other OSes use `EphemeralKeySet` ([.NET cross-platform cryptography](https://learn.microsoft.com/en-us/dotnet/standard/security/cross-platform-cryptography)). The peer implements only TLS; it is not a Dameng server or a claim of native DM interoperability. Synthetic contract vectors under `tests/fixtures/security/` contain no key material.

`eng/t07.sh real` builds the W probe, runs TLS smoke, TLS business, unknown CA under `RequireTls`, and unknown CA under `PlaintextAllowed` only through `scripts/with-dameng-tls-test.sh`, then runs a separate plaintext rejection through the existing `scripts/with-dameng-test.sh`. The isolated TLS instance is configured with `ENABLE_ENCRYPT=1`, and its self-issued CA has no CRL/OCSP source; the probe explicitly selects `TlsRevocationMode.NoCheck` for this environment only. Product default remains Online. The W smoke must report STARTUP mode 1, actual TLS 1.2 or 1.3, server version, verified TEST account/Schema and query, one successful TCP and TLS upgrade, and one socket disposal. The business probe adds a unique table, parameterized Unicode CRUD, Commit/Rollback, independent 96 KiB BLOB readback, and `finally` cleanup verified from a fresh connection. Unknown CA under both policies and plaintext mode 0 must fail before LOGIN, close promptly, and release their sockets. After these gates, the script runs `eng/t06.sh real` to preserve the existing plaintext W/T05 ownership and LOB behavior.

Every command writes a fresh ignored `.local/t07/runs/<id>` directory. The script sets a writable `DOTNET_CLI_HOME`, disables first-run behavior and telemetry, uses one MSBuild node, disables node reuse/shared compilation/build servers, and rejects any missing or nonpass TRX/result. Real stderr and raw exceptions are suppressed; JSON results contain only mode, protocol, version, outcome, resource counts, and TEST identity booleans. Official `disql` setup evidence and W real evidence remain separate. The container setup and its license limit are documented in [local-dameng-tls.md](../docs/implementation/local-dameng-tls.md).

`eng/t07.sh matrix` operates only on the owned local container. It verifies mode 1 first, switches to mode 2 for the AUTH_ONLY no-LOGIN rejection, mode 4 for a positive Open plus unknown CA rejection, and server configuration mode 5 for a positive Open. This DM image reports STARTUP wire mode **4** when configured to 5; the test records both values and treats it as verified wire-4 TLS behavior, not evidence that wire mode 5 is supported. Wire mode 5 remains explicitly unsupported. `finally` always attempts to restore mode 1, checks the official TEST login, and checks W TLS Open. Every switch verifies the exact container ID, image, port binding, and bind mounts before editing this instance's `dm.ini`. Any unsupported mode or failed restoration rejects the matrix and preserves sanitized stage results. The original shared plaintext instance is never reconfigured.
