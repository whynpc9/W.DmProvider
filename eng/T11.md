# T11 隔离级别调查入口

`bash eng/t11.sh baseline` 独立构建和运行固定 O 8.3.1.47463、只读 R DLL 和冻结 T10 W 三个进程。探针目录的 source hash、加载 DLL SHA/MVID、TEST 实际身份、唯一对象清理及独立连接最终状态均须完整。baseline_profiled 是旧实现表征，案例失败保留在结果，不能算候选正确性通过。

首轮 baseline 只运行三个级别的参数化/非参数化 UPDATE+SQL%ROWCOUNT 完整 NextResult、natural/causal 对照，作为最小根因调查（O/R 每进程 12 案例）。`matrix` 模式另准备完整 ADO 表征但尚未正式运行。完整矩阵中每个可创建级别（RC/RU/Serializable）运行参数化/非参数化单 UPDATE、UPDATE+SQL%ROWCOUNT、INSERT+identity 键回读、带/不带 SAVEPOINT 关键字的 quoted ROLLBACK TO、重复 Prepare/执行。事务外创建唯一表，事务中修改，明确 Commit/Rollback，最终关闭原物理连接并独立读回。每次 reader 遍历完整 NextResult，校验 ROWCOUNT 或真实键值；不插入改变 ROWCOUNT 的辅助查询。

O/R 分别保留 natural 和仅清除新用户 Command 继承 statement 引用的 causal 对照。同一固定 DLL，不改 SQL、参数、事务或 statement owner；这项单变量干预只供根因调查。记录用户 SQL 长度/hash、参数个数、是否继承 transaction statement、owner 是否当前用户 command、owner SQL 与实际 statement SQL 长度/hash、准备状态、timeout/type，以及脱敏异常链 type/method/line。不会输出 SQL、原始异常消息、连接串、认证或环境变量。

冻结 T10 W 的公开 RU/Serializable 拒绝单列，未执行该级别案例，不作为修复成功。Candidate 保留单次 internal profile 入口供历史诊断，完整候选 profile 验证与正常 public 验证入口如下；最终 EF 保存链按单独阶段记录。实际构建和 TEST 执行由独立 Low 验证者统一安排。

`bash eng/t11.sh offline` 运行无网络的 Command ownership/privacy 与 ROLLBACK TO 词法边界回归，要求完整 TRX 全部执行、全部通过、零 skip，并构建候选探针。prepromotion 输入已由 Low 执行 53/53（四条 ownership/privacy、25 条保存点边界、24 条隔离 receipt）。新增 public profile gate 数据点仍须 fresh run，实际发现/执行总数以 Low 的完整 TRX 报告为准，不能把预计总数当已通过。`bash eng/t11.sh real` 完整采集候选三档 × 参数/非参数 × 六种 ADO 形态（36 cases），以及独立两连接 litmus，再对全部结果严格判定。输入 hash 涵盖产品、IsolationTests、IsolationProbe、脚本/文档与 SDK pin，正常与失败路径均保存最终 hash。

候选矩阵要求 isolation control statement 不被 transaction 保留、RU/Serializable 的已确认 SET 之后出现成功 STMT_CLOSE、同连接能再用公开 RC，全部修改/ROWCOUNT/identity keys/保存点/重复执行及独立最终值正确。live user statement owner 必须等于 caller，完整 reader 和 NextResult 前均有快照。缺失任何证据或案例失败都使整轮 rejected。

RC/RU visibility 使用 A 已确认但未提交的写、B 已 Prepare 的 SELECT 与实际发送屏障。首次读如确实在 A Commit 前返回，RC 不能读到未提交值，RU 可以读到旧值或未提交值；有界锁等待允许 A Commit 后返回。二者同事务 committed 再读与 fresh 最终值必须为 1。Serializable 在 B 首次读 0 后启动 A 已 Prepare 的并发写，记录完整物理 session/lease/execution/invocation 发送身份与有界 worker 进度；B 第二读必须为 0，B 结束后 writer 要确认完成，fresh 值为 1。记录已提交 writer 下稳定快照、或 writer 在 reader 结束尝试之后完成的观察，不把任意 timeout/IO/未知冲突当成正确语义。未经单独证实的冲突类别保留待 review 并拒绝严格成功。

所有等待均由事件或 bounded Task wait 收口，不使用固定 sleep。finally 释放 reader 事务、关闭捕获连接并有界 join worker；hook/event 在同一个 gate 下设置 disposed，迟到回调不影响业务。候选 ADO/litmus 通过仍仅涵盖本次 8.1.5.60 profile/SQL 形态，EF 与正常公开 RU/Serializable 的最终能力 gate 另行完成。

`candidate-begin-trace` 仅是诊断入口：三档 internal Begin、显式 Rollback 与同连接 public RC reset，不创建表或执行业务 DML，不参与候选完整成功计数。AfterStatementDecode 只记录 retStmtType、默认 session isolation/AutoCommit 及符合 req5/ret150或166/唯一 SET 控制 statement/body4 的返回隔离 Short（绝对读取且 cursor 不变）。其它形态标 skip，不输出原帧或 SQL。已观察的 ret150 返回当前事务级别 0/3，而 session default RC 未变；不能把这一正常区别当隔离设置失败，产品须用与本次操作绑定的确切 receipt 确认。

隔离 receipt 用例覆盖已确认 ret150/req5/sql0/相同正 execution identity 下的 level 0/1/3，以及 missing、mismatch、ret166/sessiondefault 误用、未知 expected/actual level、非成功 control envelope、其它 session/generation/execution/invocation、非正 identity。真实候选仍要求完整三档矩阵与并发最终状态，receipt 单测不替代服务器语义。

`bash eng/t11.sh real-public` 调用 `public-matrix` / `public-litmus`。这两种模式把矩阵所有 Begin 与 litmus 四处 Begin 都传为 profile=false，实际执行正常公开 `BeginTransaction(IsolationLevel)`，完整三档 × 六形态 × 参数/非参数及三组并发严格契约保持相同。报告及每个案例标 `entry=public`，严格验证器同时核该标识；不借 internal profile 绕过公开能力门。公开 RU/Serializable 仅允许 exact ordinal `8.1.5.60`，其它 profile/未验证级别由离线边界验证拒绝。

本次 promotion 另将当前 T10 candidate unsupported 列表按 profile 判断：已证 `8.1.5.60` 验 RR/Snapshot/Chaos 拒绝，其它 profile 同时验 RU/Serializable 拒绝。历史 T10 source/evidence 与 O/frozen 实现未改；新 `bash eng/t10.sh offline` / `bash eng/t10.sh real` 结果计入 T11 回归证据。最终顺序为 fresh T11 offline → real-public → 当前 T10 offline/real → 固定候选 package 与 EF public 验证；各阶段不冒充另一阶段通过。
