# T10 local transaction and savepoint verification

`bash eng/t10.sh baseline` is a characterization gate against the official `DM.DmProvider 8.3.1.47463` package and the accepted T08 W binary frozen at `.local/t08/accepted-binaries/net10.0/` (SHA-256 `51e340397f64538e41d999fcf01e154bfabbf94f08704e749bf03ac7128440f0`). It uses independent executables, builds single-node with disabled build servers, and invokes each probe only through `scripts/with-dameng-test.sh`. A result is accepted only when both verify `WDM_PROVIDER_TEST`, use unique unqualified objects, and prove their absence from a fresh connection after cleanup. The status `baseline_profiled` is **not** T10 candidate acceptance.

The observed TEST server reports version `8.1.5.60`. For frozen W, `BeginTransaction(ReadCommitted)` with no business SQL sent no wire message; a following Commit sent one request and received a fully validated `requestOpcode=8,responseOpcode=0,sqlCode=0,bodyLength=28` response. Rollback of an inserted row received the same response shape for request opcode 9, and an independent connection found no row. This is the current server's ACK profile only; official O has no internal metadata hook, so its results are public transaction outcomes, not fabricated opcode evidence.

Both baselines report `SupportsSavepoints=false` at the ADO API while `SAVEPOINT`, `ROLLBACK TO SAVEPOINT`, and `RELEASE SAVEPOINT` SQL succeeded on the dedicated TEST schema. Both also showed that a DDL statement in an active transaction committed the preceding insert: a later Rollback returned successfully, yet an independent connection found both the inserted row and the DDL table. A narrowed frozen-W response hook showed why post-call cache inspection is misleading: the INSERT business response had `retStmtType=157`, `trxStatus=1`, and `getTransFinish()=false`, but its `MORE_RESULT` terminal overwrote the cache to `0/true`. The DDL business response had `retStmtType=129` and `0/true`; its terminal kept that value. T10 must use a verified response-time signal or reject DDL before send, not treat the later Rollback ACK or post-call cache value as proof that earlier DML rolled back. [Official transaction SQL reference](https://eco.dameng.com/document/dm/zh-cn/pm/consistency-concurrency.html).

The candidate gates will test TX-01–05 and TX-07–08 with deterministic control-send barriers, confirmed ACK versus OutcomeUnknown, bounded Dispose/reader cleanup, savepoint name mapping, and independent final-state readback. The complete ReadUncommitted/Serializable isolation litmus and EF SaveChanges differential remain T11. All fixtures under `tests/fixtures/transactions/` are synthetic `not_run` vectors until corresponding tests execute.

`bash eng/t10.sh offline` requires a strict TransactionTests TRX with every test executed and passed, builds the candidate probe, and runs T08 offline regression. `bash eng/t10.sh real` runs a separate `candidate_verified` envelope of ten TEST scenarios, then T08 real regression before reporting success. The real probe checks Commit/Rollback and terminal Dispose, Active Dispose with reader, ownership and stale-session rejection, public legacy-field tampering without skipped rollback, pre-send/attempt/ACK races with fresh final-state readback, quoted generated savepoints, a later SQL error with explicit rollback, DDL CompletedExternally on the verified server profile, and ambient/default ReadCommitted boundaries. No baseline observation is counted as a candidate pass.
