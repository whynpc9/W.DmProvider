# R1 无数据库 CI 与候选审计

`bash eng/t12-offline.sh offline` 从干净 checkout 顺序执行配置、session、transport、security、command、type、transaction、isolation 八个 W 测试工程。它只依赖已登记源码/fixture、SDK `global.json` 的 exact 10.0.203 与 NuGet 公共还原，不加载 `.local` 历史 DLL、数据库 secret 或下游私网实例。离线指无数据库；首次 restore 仍需公共 NuGet 网络或事先准备的包。

每个 restore/test 使用单节点、no node reuse、no shared compilation 和关闭 build servers。测试 host 退出码、超时、完整 TRX counters、实际结果个数、每条 outcome 与 RunInfo error 都严格核对；任何 skip/abort/crash/缺失结果拒绝整轮。所有八个工程均执行，不能用部分计数替代总成功。source inputs 前后 SHA 清单一致才成功。dotnet subprocess 超时从创建开始；到期只终止该次独立进程组，不控制其它仓库进程。

结果默认保存到新的 ignored `.local/t12-offline/runs/<id>/`，CI 用 `R1_RESULTS_DIR` 指定 runner temp。`.private` 存原始 build/restore/test 输出和临时 NuGet/cache；只上传 `public` 中的 host exit/counters、安全 TRX、精确依赖 identity/hash、SDK 与 source 清单。TRX 在原件验证后去除任意 stdout/stderr/异常消息/附件/RunInfos，测试名移除实参数；不会将私钥、证书、NuGet cache、连接配置或原始输出加入 CI artifacts。通过只报告 `offline_verified` 和 `integration_pending`。

`.github/workflows/r1-offline.yml` 固定三个已核实 action commit，按 exact global.json 安装 SDK，在 Ubuntu 24.04 执行该入口及缺环境反例。当前仅完成本地/干净 checkout 验证后才能报告相应证据；工作流存在不代表 GitHub Actions 已实际运行。

## 发布环境预检

```sh
bash eng/t12-offline.sh release-environment
```

缺 `DAMENG_TEST_CONNECTION_STRING` 直接非零 66，发生在 SDK/build/restore/login 之前。非空时构建独立小工具，复用 W typed builder 的 quoting、aliases、重复键校验，实际 User 必须为 TEST；Password 字面量中的 User Id 不能冒充账号。SDK 查询、restore/build 使用移除 TEST 变量的环境；只给最终安全 C# 配置检查子进程传该唯一变量。不输出连接串或异常 Message。这只是配置预检，不登录数据库，也不输出 release passed；服务器 USER、真实下游、最终状态与完整发布门由 T12 真实 acceptance host 独立验证。不会创建或复制 CI secret，不假设 CI 能访问本机私网。

## 精确候选包与当前 API

```sh
bash eng/t12-offline.sh package-audit \
  --package /absolute/path/W.DmProvider.VERSION.nupkg \
  --version VERSION \
  --package-sha256 PRODUCER_PACKAGE_SHA256 \
  --dll-sha256 PRODUCER_DLL_SHA256 \
  --source-sha256 PRODUCER_SOURCE_SHA256
```

版本必须为严格唯一 `0.1.0-(t11|t12|r1).YYYYMMDDHHMMSS`；包 ID 固定 W.DmProvider，包/DLL/source hash 全部从 producer 冻结证据显式给出，不能用 latest 或可变指针。Source SHA 使用 T03 path-plus-file-SHA256 算法（含第三方 notices），但 R1 明确排除产品目录中的临时 NuGet.Config、OS metadata 与 bin/obj/.local/__pycache__。producer 使用 `bash eng/t12-offline.sh source-hash` 取得同一 R1 SHA；审计复制该精确 filtered source snapshot 交既有 T03 package 检查器，并输出 included/excluded 清单。历史 T03/T11 hash、来源记录和工具不回写。最终 R1 由 root 创建全新 r1 timestamp 包并以同一 hash 做 EF 验收，不覆盖历史版本。

审计复用 T03 package 检查和实际 PackageReference consumer：必须确实只有 W 的 `lib/net10.0` 主 DLL 与四个 satellite，无官方 DLL、native/runtime assets、额外 nuspec 依赖。独立 exact local feed/cache 中还原并加载 package DLL，核 actual `.deps.json`/assembly references/resources 和 SHA，绝不以 ProjectReference 代替包消费。

当前公开 surface 从本次包 DLL 经既有 RestoreBaseline Mono.Cecil exporter 导出，再与 T03 mapped surface 比较，生成 `public-api-current.txt` / `public-api-delta.json`，包括 T09 DmDecimal、T10 Outcome/Unknown 等新增 API 的实际列表。旧 T04 api-diff 不能冒充最终 surface。静态导出不证明每个 legacy API 行为已通过。

`public` 同时保存 producer-matched 包/源码 manifest、actual package consumer、当前 API hash/delta、来源材料清单和产品 CycloneDX 1.6 SBOM（包/file hashes 与空 product dependency group；来源 ancestry 另附，不列为官方 runtime dependency）。来源引用现有 T03 source map、upstream manifest 与 THIRD-PARTY-NOTICES，不重复造来源证据。offline suite 的 tooling dependency inventory 单独记录；产品实际 framework assembly references 来自实际 consumer。支持/未支持矩阵与下游/真实库 evidence 属最终 R1 handoff，不用离线 CI 或静态审计替代。

最终 producer/Low 可显式设置非秘密 `R1_CANDIDATE_VERSION=0.1.0-r1.YYYYMMDDHHMMSS`。offline 将 exact `/p:Version` 一致传给八套 restore/test，全部使用 Release 配置，记录 `build-properties.json`；未设置时 CI 使用项目默认版本并仍只声明 offline。最终 pack 必须使用同一 Version/Release 与已验证 DLL，不仅改 PackageVersion/nuspec。旧 T11 PackageVersion-only/no-build 包 informational version 不同，预期不能通过最终 R1 package-audit，不应放宽 T03 actual consumer 的严格 Version 校验。

会重建 W 的配置 guard 同样传该 Version，但 BaseOutputPath 隔离到本次 `.private/environment-build`，避免覆盖最终 `src/W.DmProvider/bin/Release` DLL。package consumer 只有 exact PackageReference，surface exporter 不引用 W 项目；这两类工具不重新构建或覆盖产品 DLL。配置 guard 只最终 check 子进程继承 TEST secret，所有 SDK/restore/build 均移除该变量。
