# T03 independent candidate package probe

This is a local development candidate, not a release. Run from the repository root:

```sh
eng/t03.sh pack
eng/t03.sh offline
eng/t03.sh api
eng/t03.sh real
```

`offline`, `api`, and `real` also accept the exact candidate version as their
only extra argument. Use that form for independent acceptance so a newer
candidate cannot change the test target through the `version` pointer.

`pack` builds `src/W.DmProvider/W.DmProvider.csproj` directly. It creates a unique
`0.1.0-t03.YYYYMMDDHHMMSS` version and refuses an existing version directory.
The local feed and SHA-256 manifest are in `.local/t03/packages/<version>/`; the
current candidate version is `.local/t03/packages/version`. No upload occurs.
The manifest lists every binary asset hash, package hash, source tree hash,
and exact version. The package check parses the nuspec and checks package ID,
version, `net10.0` dependency group, license, and absent repository commit. It
requires exactly the W main DLL and four W satellite DLLs, a license and source
notice; it rejects official DLLs, native binaries, and runtime assets.

`offline` and `real` restore a separate net10.0 consumer with a `PackageReference`
to that exact version from only that local feed. The NuGet cache and build output
are isolated per candidate. There is no `ProjectReference`. The consumer compares
the loaded W DLL SHA-256 with the archive entry, checks actual assembly references
and its `.deps.json`, verifies core type ownership and factory registration, and
directly opens neutral and each culture's `.resources` stream. It checks both
satellite bytes and resource-value hashes; a fallback resource cannot satisfy the
direct stream check. `CanCreateBatch` must be false.

`api` uses the existing RestoreBaseline API extractor on the consumer's copied W
DLL and checks `docs/compatibility/t03-api-map.json` against all 3,651 original
signatures and every actual W export. It checks unique coverage, classifications,
verification states, and reasons; the mapping is authored by the product lane.

`real` is the only action that loads `.local/secrets/dameng-test.env`, via
`scripts/with-dameng-test.sh`. Before SQL it verifies both parsed and server
account `WDM_PROVIDER_TEST`. It uses a random table in that account's schema for
bounded Unicode parameter CRUD and explicit commit/rollback, then uses separate
connections to verify state and cleanup. It does not exercise advanced features.
Without `real`, report `integration_pending`.

All actions emit one JSON result on stdout; build details remain in ignored
`.local/t03/` logs. Error JSON contains only a stage, exception type, and safe
numeric `Number`; it never prints connection strings or raw exception messages.
Nonzero exit or missing fresh result is a failed run. Official O and restored R
evidence is recorded separately under T02 and is not attributed to this W probe.
