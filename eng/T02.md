# T02 O/R comparison harness

The two net10.0 hosts compile the same `tools/BaselineComparison/Shared/Program.cs`.
`Official/Official.csproj` restores only `DM.DmProvider 8.3.1.47463` from the local
`packages/` source. `Restored/Restored.csproj` references only
`.local/t02/restored/DM.DmProvider.Restored.csproj`. Each host has its own output,
NuGet cache, process, and JSON result. The host checks the loaded DLL SHA-256 and
MVID; R also checks its loaded DLL against the restored build output. R cannot
silently load the official DLL.

Commands from the repository root:

```sh
eng/t02.sh build-o
eng/t02.sh build-r
eng/t02.sh offline-compare
eng/t02.sh api
eng/t02.sh compare
```

`offline-compare` validates the fixture hashes, the synthetic `InitialCatalog`
setter defect, the eight `decStringToBcd` repair cases, and resource lookup for
neutral, en, zh-CN, zh-HK, and zh-TW. A separate reflection check verifies
that the internal `A.D` receive method still overrides the `A.a` virtual slot;
matching method bodies alone cannot establish this dispatch relationship. It checks that every localized satellite
exists and records its file hash separately from the resolved resource value
hash. `api` emits sorted public/protected type and member signatures, including
constants and optional defaults, then reports exact set differences. Neither
command opens a database connection.

`compare` runs O then R, loading only the test account via
`scripts/with-dameng-test.sh`. Both hosts verify `WDM_PROVIDER_TEST` in the
parsed connection options and from `SELECT USER FROM DUAL`. It covers all nine
S01 scenario IDs. The write scenarios use separate random tables in the current
schema and bind values as parameters. Each table is removed in `finally`, then
a separate connection checks `USER_TABLES` for absence. Commit/Rollback state
is read through separate connections. The S05 DML plus `SQL%ROWCOUNT` and
`SCOPE_IDENTITY()` examples remain one `CommandText` each, with no client
semicolon splitting or intervening query.

The wrapper prints one JSON document to stdout. Build progress and local result
paths go to stderr. JSON and build logs stay under ignored `.local/t02/evidence/`.
Results contain no connection string, password, raw exception message, or
authentication data. Exceptions use type and safe numeric `Number`; a rejected
connection can include method names in a bounded diagnostic chain. The optional
`eng/t02.sh diagnose-r` runs one R open with a bounded first-chance exception
ring, again recording only types, numbers, and method names.

`verified` requires distinct driver binaries, successful O and R process exits,
all nine expected scenarios, each semantic assertion, independent cleanup,
resource equivalence, and repair-case equivalence. Equal O/R failures are
reported as behavior observations, never as correctness. `host_rejected` means
one host stopped before emitting its complete result. O, R, and comparison JSON
remain separately available for review.
