# T19 immutable candidate gate

由独立 Low 在整体源码冻结后执行；编码 agent 不运行构建或实库。此入口不 commit/push/tag/publish，不把离线候选或外部 `status=passed` 当完整 R3 发行验收。

```sh
DOTNET_COMMAND=/usr/local/share/dotnet/dotnet eng/t19.sh offline
eng/t19.sh matrix <absolute-candidate-run> tls
eng/t19.sh matrix <absolute-candidate-run> shared
eng/t19.sh external-preflight <absolute-candidate-run> <evidence-index.json>
eng/t19.sh release-environment
```

`offline` 生成 `0.1.0-r3.YYYYMMDDHHMMSS` UTC 版本并在 ignored 版本目录排他保留；可显式设置同格式 `R3_CANDIDATE_VERSION`。已保留版本或已存在运行目录一律拒绝，失败版本也不能覆盖。runner 明确把该版本传给现 `R3ReleaseAudit`，在冻结副本完成全部十二套、同 Version 的 no-build/no-restore pack 和七个 first-init 包子进程。SDK 必须是 global.json 固定的 10.0.203；CLI home/cache 独立可写、首启和 telemetry 关闭、单节点/noReuse/noSharedCompilation/disable-build-servers。不清全局缓存。

完整源码清单包含当前 src/tests/tools/eng/scripts/docs/.github 与根构建/许可材料，包括未 tracked 的本轮文件。bin/obj/.git/.local/cache 不进入 archive；任何非排除目录 symlink、env/私钥文件均拒绝。decompiled/upstream/packages 属来源祖先材料，不是本轮编译输入或 runtime 依赖；其来源通过固定 source-map 和 notices 哈希记录。tar.gz 解压逐文件字节、模式和清单哈希重建，再在副本执行验证，验证后 frozen/live source 必须都等于原清单。保存 HEAD 与包含未 tracked 文件的 working-tree diff hash；不输出 diff 内容。SourceLink 保持 false，不声称 SourceLink 可验证。

独立 exact PackageReference consumer 导出实际加载 DLL SHA/MVID、public API metadata、runtime/OS/RID 与实际 assembly references。nupkg nuspec/二进制 assets/README/许可证和 notices 校验，依赖树明确分 runtime、tests 与工具；CycloneDX 把测试依赖标 validation-only/excluded，不将 DM 源祖先冒充 runtime NuGet dependency。源码中的合成敏感 control 保留供验证；公共安全结果禁止这些 marker、私钥及原始异常/凭据输出，private 构建日志不上传。

候选身份统一位于 `run/public/candidate.json`：version、package_sha256、driver_dll_sha256、driver_mvid、source_manifest_sha256。最后字段是 `source-manifest.json` 本身 SHA，与 tree_sha256 不同。immutable feed 位于 `run/private/feed`，包完成后设只读。public archive/source provenance 与 API/依赖/SBOM 构成可复核材料。

producer snapshot 包含冻结当时的 docs；从 offline 到 TLS/shared/EF 和 external preflight 整个窗口保持这些输入不变。新验证输出只写 ignored candidate/matrix 运行目录，root 在窗口结束后才归档 evidence、更新报告或 progress。窗口结束后的档案 readback 依据 immutable source archive/manifest，不声称报告回写后的 live tree 仍逐字相同。本轮 `matrix/external-preflight` 只供严格冻结窗口内调用，不为生成报告而松动产品、tests 或 tools 的 source identity。

`matrix` 仅调用现有精确包工具，运行前后包/source 身份不变。每 profile 包含 T16、T17、R2 T13 原异步大负载、T14 取消/Unknown 与 T13 安全拒绝门；TLS 另执行预先规定的 T18 TLS600秒资源门。外层预算只容纳内层原预算和 consumer build，不修改旧原始负载/调用期限。无 TEST secret 环境返回66；不读管理 secret、不改变 shared 实例/授权，不自行维护先前残留对象。shared 资源门如实 `not_verified_not_required`，不额外增加阻断。shared stream、R2原门、授权的精确旧对象 cleanup 和最终 EF 仍必需。

`external-preflight` 的索引格式为 `{"schema_version":1,"reports":{"ef_final":"/path/summary.json", ...}}`。报告必须绑定全部 candidate 身份和已知 rich schema/validator 文件哈希；EF 固定 commit `113014cc74dd1f751ef97226a78d2ec855b32c8c`、archive SHA `9dead07c1de4220bd13bdadab0ed2713f43008af5e7c0cf7a629549a6739096d`、EF Core10.0.12/SDK10.0.401，并携各 lane TRX/case/host/CLI/fresh audit/锁及实际 DLL 证明。它只输出 envelope preflight、missing gate 与 matrix_pending，不能根据任意布尔“通过”关闭最终门。没有独立 exact-cleanup 报告时继续 missing。root 最终逐项 readback 决定 readiness；旧 T18 `upstream_pending` 是阶段历史，不作为可被覆盖的完成状态。
