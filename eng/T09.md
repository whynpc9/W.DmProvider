# T09 参数与类型测试入口

`bash eng/t09.sh baseline` 使用固定官方 8.3.1.47463 包和 SHA-256 为 `51e340397f64538e41d999fcf01e154bfabbf94f08704e749bf03ac7128440f0` 的 T08 已验收 W DLL，分别构建并运行独立进程。先从旧 `DmdbNumeric` 编码器和另一路 `DmXDec.StrToDec`/`Parse` 读取六组独立表征，再经 `scripts/with-dameng-test.sh` 运行 O/冻结 W 的 TYP-01–09 观察探针。首次旧 DLL 实测 `DmdbNumeric` 六组字节与 T09 精确 codec 候选向量全部不同，已将旧字节固定为**旧路径观察值**而非新 wire 正确契约；`DmXDec` 活跃路径的独立实测表征见下方证据。身份、结果结构、唯一对象清理完整才可标 `baseline_characterized`；旧错误从不作为新正确断言。

`bash eng/t09.sh offline` 运行 `W.DmProvider.TypeTests` 中的精确 decimal、固定旧编码向量、坏 wire、严格字符编码、时间精度和参数本地契约，再构建候选 probe。严格检查完整 TRX，无数据库时结果为 `integration_pending`。26 条合成 fixture 保持 `not_run`，不能冒充执行结果。

`bash eng/t09.sh real` 只用 TEST wrapper，对当前候选 W 运行 TYP-01–09 数据、字段元数据、provider-specific 值、异常类别及独立连接最终状态 probe。输出只含合成数据、类型名、计数、散列和结构化错误类别；不含连接串、口令、原始异常消息或任意服务端文本。严格验证器会拒绝 enum/unsigned/decimal 精度损失、GUID 文本误判、Unicode 丢字、半代理项或溢出值出现可观察执行结果帧、NULL/空二进制混淆、参数冲突被接受、同步/异步值或异常不一致。传输 send 计数单独记录；无结果帧不能独自证明没有任何前置 describe 请求。候选 TYP-06 还强制验证目标 profile 的 ±1 微秒、负多天 INTERVAL、DateOnly/TimeOnly、正负偏移 DTO 六位精度、不可表示第七位及 TimeSpan.MinValue 明确拒绝；CHARSET 从已协商连接记录，并用真实 Unicode 回读与离线 UTF-8/GB18030 编码负例限定范围。EF `GetString` 的 INTERVAL、CLOB 和时间文本形态均须通过严格断言。全部九组通过仍只表示该服务器 profile 的 T09 范围；完整 EF 应用消费留 T12。

二进制长度反例在同一 TEST 随机表的已存在行上执行：`Binary`、`VarBinary`、`Blob` 的显式 `Size=16` 各绑定 17 字节；每次候选必须抛 `OverflowException`，用新连接验证原行二进制或 NULL BLOB 状态未变。NULL 和空 byte[] 另测，不能把服务器实际行为推定为相同。

GUID 测试在同一唯一对象中分别用字符串、byte[] 以及真正 CLR `Guid` 值。CLR `Guid` 对 `VARCHAR(50)` 走 `DbType.String`，对 `VARBINARY(16)` 走 `DbType.Binary`，新连接核对均非 NULL 且显式 `GetGuid` 相等；对 `VARBINARY(15)` 的同一 16 字节值须拒绝且原 NULL 不变。NULL 绑定另有四个窄 probe：无类型 `SELECT :p`、显式 Int32 NULL、`CAST(:p AS INT)` 和 nullable INT 列 INSERT。只记录参数 ordinal、Prepare 后 CType/SqlType/Precision/Scale/TypeFlag/mask、Prepare/Execute 状态与发送计数、结果型和独立连接最终状态，不输出 SQL/值。可靠 describe 的判定必须依实际 profile，不能把某次旧默认绑定误当新契约。

候选首次真实 profile 已生成全部九组并通过身份与清理，但严格门在 UInt64 数值处拒绝，完整离线诊断保存在 `.local/t09/runs/20260929T183241Z-3820-4076/candidate_diagnostic.json`。诊断仅用于分派，不改失败结论。后续窄 probe 将对 UInt64/ulong enum 各做裸 SELECT 与 `CAST(... AS DECIMAL(38,0))` 的 Prepare 前后参数型别/编码长度比较；INTERVAL 参数做默认与显式 Precision/Scale+CAST 对照；四组 NULL 追加 TypeSource 与执行后 metadata。此处只输出数值型别、异常类别与结果型，不输出参数值、SQL 正文或 wire 字节。

INTERVAL `GetString` 还记录与已审阅下游 `DamengTimeSpanTypeMapping.Parse` 相同的引号 payload 形态能否解析及 ticks；普通 `TimeSpan.TryParse` 单独标作框架解析结果。此处是源码固定的形态检查，T12 的真实 EF 消费者仍须独立验证。

每个实库 probe 先核对 `WDM_PROVIDER_TEST` 实际服务器身份，只创建本次随机 `T09_` 表，在 `finally` 精确清理，并用新连接确认不存在。O、冻结 W、候选 W 各有独立 DLL hash/MVID 与 JSON 结果。唯一 build/DB 窗口由测试负责人协调；运行前须确认生产 lane checkpoint，不能与 T10 并发。失败时脚本只报告阶段和退出码，原始输出留在忽略的 `.local/t09/runs/`，不要外传可能含凭据的日志。

## 已执行的分段证据

`offline` 首次因生产源码编译 8 处错误退出 1；修复后一次 TypeTests 29/29 通过但生产源码在运行中变化，source-hash gate 退出 1，整轮不计通过。四 owner 重新冻结后的 fresh `bash eng/t09.sh offline` 退出 0，TRX `29/29`、无跳过，仍为 `integration_pending`，记录于 `.local/t09/runs/20260929T180849Z-90621-6827/`。

`baseline` 首次因把旧公开 `DmdbNumeric` 的字节误当新精确 wire golden 而退出 1；两份独立旧 DLL 实际观察到相同的错误 helper 输出。随后分离该 helper 与活跃 `DmXDec.StrToDec`，一次 probe 自身编译错误退出 1，均未连接数据库。最终 `bash eng/t09.sh baseline` 退出 0，记录于 `.local/t09/runs/20260929T181336Z-93022-15586/`：官方 O 与冻结 T08 W 的 `DmXDec.StrToDec` 六值字节及 `Parse/ToString` 完全相同，分别为 `C00B`、`3F5B66`、`C002`、`3F6466`、`C10218`、`3E644E66`；显式 `DbType.Decimal` 写入 `DECIMAL(38,20)` 后，六值经独立连接 `GetDecimal` 均精确相等。旧 `DmdbNumeric` 输出另存 observed defect，不作为候选合格条件。两进程各核对 TEST 身份、九组 profile、清理前 12 行，`finally` 后新连接确认唯一对象不存在。

上述基线结果是 O/冻结 W 表征，不能替代候选 W 的真实往返或 TYP-01–09 验收。

随后加入真实 CLR Guid、二进制容量、时间精度和 NULL 元数据 probe 的 fresh `offline` 退出 0、TRX `33/33`（`.local/t09/runs/20260929T182924Z-2017-12967/`）；更新的 O/冻结 W `baseline` 再次退出 0、两边清理成功（`.local/t09/runs/20260929T182935Z-2132-4674/`）。候选 `real` 的 probe 完整运行并核对 TEST 身份及 fresh 清理，但严格验证器在 UInt64 值损失处退出 1，**整轮候选未通过**（`.local/t09/runs/20260929T183241Z-3820-4076/`）。`diagnose.py` 从该一次结果聚合所有组的偏差，保存在同 run 的 `candidate_diagnostic.json`；后续严格门失败时脚本也自动保存聚合诊断。诊断不改变原 gate 失败。

候选已观察的偏差为 UInt64 与 ulong-backed enum 回读为 Int64 `-1`、显式 DateOnly/TimeOnly 的 typed getter 失败、裸 INTERVAL 参数 ±1 微秒和负多日绑定抛溢出、无类型裸 `SELECT :p` NULL 被服务端默认 TIME 描述接受。后续控制变量只比较裸与 CAST 的准备描述及绑定后元数据，不输出值、SQL 或报文。当前不能据此判定 INTERVAL 抛错是服务端范围还是探针缺失精度设置；不能把 NULL 默认 TIME 当可靠 describe。目标实例在候选连接中报告已协商 `gb18030`，这只固定本次 charset profile。
