# T04 test and probe commands

The runner is `eng/t04.sh`. It sets a writable `DOTNET_CLI_HOME`, disables first-run behavior and telemetry, and invokes .NET with one MSBuild node, no node reuse, no shared compilation, and disabled build servers. Each run gets a fresh `.local/t04/runs/<id>` directory. A failed command emits a structured rejection with its stage and exit code; logs and TRX stay under that ignored directory. Offline success requires `passed=executed=total` and every failure, skipped/not-executed, aborted, or pending TRX counter to be zero. The real probe's success JSON is validated before it is printed. No historical T03 result is used to determine T04 success.

| Command | Purpose | Database |
|---|---|---|
| `eng/t04.sh offline` | Restore pinned xUnit dependencies, run configuration tests, build the T04 probe. Emits test counts and `integration_pending`. | None |
| `eng/t04.sh real` | Build and run the T04 probe through `scripts/with-dameng-test.sh`. | `WDM_PROVIDER_TEST` only |
| `eng/t04.sh api` | Use the existing read-only API extractor and compare the current W surface with T03's accepted map. Writes `docs/compatibility/t04-api-diff.json`. | None |

The real probe parses the local test connection without printing it, checks the configured user, explicitly sets `TransportSecurity=PlaintextAllowed`, `PersistSecurityInfo=false`, and `Schema=WDM_PROVIDER_TEST`, then checks `SELECT USER FROM DUAL` and the connection's current Schema after every opened connection. It uses only an unqualified, random `T04_` table under the test account. It verifies parameterized Unicode CRUD, commit visibility and rollback with an independent connection, configuration mutation rejection during Connecting, Open-event reentry rejection, redaction after Open and Close, failed-reopen redaction, and authentication through Clone and reopen. Its final cleanup queries `USER_TABLES` for that exact random name, drops only that table if present, and verifies absence. Output contains status, stage, result booleans, exception class/number and object name, never exception messages, raw connection strings, passwords or authentication packets.

The offline suite covers public configuration and guard behavior; the real probe is a separate result. The default `RequireTls` policy rejects before socket use. The production handshake calls an internal guard, tested with `Encrypt=1/2/4` and independently with `Encrypt=0` plus password/message encryption flags. No controlled peer protocol negative test triggers those server responses in T04; their end-to-end runtime verification belongs to T07 or a later transport fixture. Tests do not claim completion of TLS support, async deadlines, or later capability phases. A failed or absent real run remains `integration_pending` or `not_verified` as reported, even when offline tests pass.
