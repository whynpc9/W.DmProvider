# T08 command and reader verification

`eng/t08.sh baseline` uses the frozen T07 W binary at `.local/t08/baseline-w/net10.0/` and the pinned official `DM.DmProvider 8.3.1.47463` package. It builds two isolated `CommandProbe` executables, runs both only through `scripts/with-dameng-test.sh`, verifies the loaded SHA-256/MVID, TEST account, unique-object cleanup, and 13 observed command scenarios. It reports `baseline_characterized`, not a T08 acceptance pass. The frozen W SHA-256 is `ae42d4aa9df4af8bf0874dd28056b6b2704f34677a28d34f44d0df200a66a4e5`. A fresh T08 production build cannot change this baseline binary.

`eng/t08.sh trace` builds the current candidate and runs a targeted metadata-only protocol trace through the same TEST wrapper. Trace events contain only request/response opcode, SQL code, declared wire body length, result type, row count, affected count, column count, has-rowset, terminal flag, and operation stage. They contain no SQL, parameter values, frame body, credentials, or raw exception text. This mode is diagnostic and is never counted as CMD-01–08 acceptance.

`eng/t08.sh offline` runs the strict `W.DmProvider.CommandTests` TRX gate, builds the candidate probe, and runs T07 offline regression. Offline success reports `integration_pending`. `eng/t08.sh real` requires the separate `candidate_verified` result to pass 24 real TEST scenarios and all contract assertions with no failures, a final zero-row state before cleanup, and fresh random-object absence. It then runs T06 real regression (including T05 ownership) and one current-source T07 TLS smoke before emitting success. These tests cover CMD-01–07: DML 0/1, SQL%ROWCOUNT and generated identity/sequence columns, empty and multiple rowsets, later errors with proven same/fresh connection state, scalar empty/DBNull, literal/comment semicolons, repeated Prepare and user transaction, mixed `CommandBehavior`, local `GetSchemaTable` with unknown key metadata and no extra wire, early Close and command disposal, bounded prepared cleanup, binary-parameter failure without replay, and 96 KiB BLOB across a second result. Pure SELECT and unproven compound DML aggregate `RecordsAffected` must be -1; explicit ROWCOUNT row values are checked separately.

`eng/t08.sh package` packs the current candidate to a fresh ignored directory, verifies the NuGet binary set and source SHA with the T03 package inspector, restores `CommandProbe.Package` from that nupkg into an isolated NuGet cache, and runs the same `candidate_verified` TEST contract through `PackageReference`. The runtime dependency graph must identify W.DmProvider as a package, and the loaded DLL SHA must match the nupkg asset. Package acceptance is distinct from the project-reference candidate run and serves CMD-08.

Every probe creates only unique unqualified `T08_` objects in `WDM_PROVIDER_TEST`, verifies the server identity before work, and drops them in `finally` with fresh TEST connections proving absence. Official, frozen W, candidate W, and package-consumer results remain distinct. Synthetic fixtures under `tests/fixtures/command-results/` remain `not_run` and do not substitute for real-provider evidence. Identity and sequence SQL follow the [official table syntax](https://eco.dameng.com/document/dm/zh-cn/pm/management-table) and [official sequence syntax](https://eco.dameng.com/document/dm/zh-cn/pm/definition-statement.html); the real probe verifies the specific server response rather than inferring support from syntax alone.
